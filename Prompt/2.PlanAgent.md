왜수학 프로젝트의 두 번째 단계로
디자인 시스템 기반 프론트엔드 구현을 준비한다.

이번 작업에서는 실제 서비스 화면이나 공통 컴포넌트를 구현하지 마라.

먼저 plan-agent를 사용해 현재 프로젝트 상태와 기존 설계 구조를 분석하고,
그다음 design-agent를 사용해 README.md에 연결된 Figma 디자인 시스템과
현재 문서·코드의 일치 여부를 검토해라.

분석 결과와 구현 계획만 보고하고,
내가 승인하기 전까지 파일을 생성하거나 수정하지 마라.

[Figma URL 확인 방법]

프로젝트 루트의 README.md에 있는 ‘Figma 원본’ 항목을 읽고
다음 두 링크를 구분해서 사용해라.

1. ‘WhyMath Design System’ 링크
   - 디자인 토큰, 스타일, 컴포넌트 목록을 확인하는 최우선 기준이다.
   - 해당 링크의 node-id가 가리키는 디자인 시스템 영역을 직접 확인한다.

2. ‘Figma 파일 URL’ 링크
   - 실제 서비스 화면과 프레임을 확인하는 기준이다.
   - 디자인 시스템의 컴포넌트가 각 화면에 어떻게 적용됐는지 검토한다.

Figma URL을 프롬프트에 별도로 복사하거나 임의의 URL로 대체하지 말고,
항상 현재 README.md에 기록된 링크를 기준으로 접근해라.

Figma MCP 또는 현재 연결된 Figma 분석 기능을 우선 사용한다.
Builder.io는 이번 분석에서 보조적으로만 사용할 수 있으며,
Builder.io 생성 코드를 프로젝트에 추가하지 마라.

[Figma 접근 원칙]

Figma에 정상적으로 접근할 수 있다면 단순히 화면 이미지만 보지 말고
다음 구조 정보를 가능한 범위에서 직접 확인해라.

- Page와 Frame 구조
- Component와 Component Set
- Variant와 Component Property
- Variable과 Variable Collection
- Color, Text, Effect, Grid Style
- Auto Layout
- Constraints와 Resize 설정
- 컴포넌트 중첩 구조
- 인스턴스와 원본 컴포넌트의 연결 관계
- iPad 가로·세로·Split View 대응 방식

Figma URL에 접근할 수 없다면
Figma를 확인했다고 가정하거나 주장하지 마라.

스크린샷이나 ZIP을 보고 Figma의 Variable, Variant,
Auto Layout 설정을 확인한 것처럼 추측하지 마라.

접근하지 못한 경우에는 다음을 명확히 보고해라.

1. 접근하지 못한 URL 또는 노드
2. 접근 실패 원인
3. 실제로 확인한 자료
4. 추가로 필요한 자료나 연결 설정
5. Figma 확인 전에는 확정할 수 없는 항목

[디자인 기준 우선순위]

1순위: README.md의 ‘WhyMath Design System’ 링크
2순위: README.md의 ‘Figma 파일 URL’에 있는 실제 화면
3순위: Figma에서 확인한 Variable, Style, Component 정보
4순위: README.md에 설명된 디자인 시스템 기본 구조 ZIP
5순위: 화면 구조와 콘텐츠 확인용 iPad 수학 튜터 앱 ZIP
6순위: 기존 설계 문서와 현재 코드

Figma와 ZIP 또는 기존 문서의 값이 다르면 Figma를 우선한다.

README.md에 명시된 것처럼
디자인 시스템 기본 구조 ZIP에서는 다음 항목을 중심으로 참고한다.

- Math Material — Button
- Math Material — Card
- Math Material — Tabs
- Math Bold-3D — Elevation
- Math Bold-3D — In Use

단, ZIP의 코드를 프로덕션 코드에 그대로 복사하지 마라.
ZIP은 구조와 의도를 파악하는 참고 자료로만 사용한다.

[design-agent 검토 범위]

design-agent는 README.md의 Figma 링크를 기준으로 다음을 검토해라.

1. Primitive Color
2. Semantic Color
3. Typography
4. Spacing
5. Border Radius
6. Border
7. Shadow와 Elevation
8. Breakpoint와 Safe Area
9. Component Token
10. Button, Card, Tabs 등 공통 컴포넌트
11. Variant, Size, State, Property
12. 컴포넌트의 Auto Layout과 반응형 규칙
13. iPad 가로·세로·Split View 대응
14. 기존 문서 또는 코드와 Figma의 불일치

특히 다음 사항을 확인해라.

- Figma에는 있지만 문서에 누락된 토큰
- 문서에는 있지만 Figma에서 확인되지 않는 토큰
- 동일한 값이 서로 다른 이름으로 중복 정의된 경우
- Figma Variant와 코드 컴포넌트 Variant의 불일치
- 공통 컴포넌트로 분리해야 하는 반복 UI
- 임의 색상값과 임의 픽셀값
- ZIP 구조가 Figma 최신 디자인과 다른 부분

design-agent도 파일을 수정하지 말고 검토 결과만 보고해라.

[중요 제한]

- 아직 파일을 생성하거나 수정하지 않는다.
- 패키지를 설치하지 않는다.
- 실제 서비스 화면을 구현하지 않는다.
- Builder.io 생성 코드를 가져오지 않는다.
- Figma에서 확인되지 않은 값을 임의로 만들지 않는다.
- API, Supabase, 로그인, AI, 필기 캔버스 기능을 구현하지 않는다.
- 확인하지 못한 내용을 추측으로 확정하지 않는다.
- 분석 결과를 먼저 보여주고 내 승인을 기다린다.
