먼저 다음 문서와 현재 저장소를 직접 확인하고, 문서에 없는 내용을 추측하지 마라.

* `docs/PRD_WHYMATH.md`

기존 파일과 설정이 있으면 불필요하게 교체하거나 중복 생성하지 말고, 현재 구조를 유지하면서 필요한 최소 변경만 제안한다.

# 1. 이번 지시의 우선순위와 범위 변경

이 지시는 이전 프롬프트의 다음 내용을 대체한다.

* “이번 단계에서는 로그인 인증 로직을 구현하지 않는다.”
* “`/`를 인증 상태와 관계없이 `/solve`로 임시 리다이렉트한다.”

이번 통합 작업에는 다음이 포함된다.

1. pnpm workspace 기반 프로젝트 구성
2. `apps/web` React + TypeScript + Vite 구성
3. React Router 기반 라우팅
4. Tailwind CSS 4 연결
5. iPad 가로 전체 화면용 `ViewportGuard`
6. PWA 기본 설정
7. 라이트 모드 고정
8. Figma에서 확정된 색상 토큰 이식
9. typecheck, lint, test, build 검증 구성
10. PRD의 AUTH 요구사항 반영
11. 인증 상태 관리와 세션 복원 구조
12. 로그인 성공 후 `/solve` 이동
13. 보호 라우트와 로그인 전용 라우트 구성
14. 로그아웃 후 `/login` 이동

단, 로그인 화면의 최종 Figma UI 디자인은 이번 범위가 아니다. 기존 로그인 UI가 있으면 유지하면서 인증 로직만 연결하고, 없다면 임의로 최종 디자인을 만들지 말고 필요한 최소 기술 UI 범위를 먼저 보고한다.

# 2. 프로젝트 구조

v1은 `apps/web` 단일 앱 중심으로 구현한다.

* Turborepo와 Nx는 도입하지 않는다.
* pnpm workspace만 사용한다.
* `packages/ui`
* `packages/shared-types`
* `packages/validation`

위 패키지는 현재 생성하지 않는다.

둘 이상의 앱이나 백엔드에서 타입을 실제로 공유하게 될 때만 `packages/contracts` 도입을 검토한다.

공통 코드 위치는 다음 기준을 사용한다.

* 앱 설정 및 라우팅: `apps/web/src/app`
* 페이지 조립: `apps/web/src/pages`
* 기능 코드: `apps/web/src/features`
* 공통 UI: `apps/web/src/shared/ui`
* 디자인 토큰 및 전역 스타일: `apps/web/src/shared/styles`

# 3. 확정 라우트

`docs/FIGMA_SCREEN_MAP.md`를 기준으로 다음 라우트를 구성한다.

1. `/login` → `LoginPage`
2. `/grade-setup` → `GradeSetupPage`
3. `/solve` → `SolvePage`
4. `/mypage` → `MyPage`
5. `/camera` → `CameraCapturePage`
6. `/camera/preview` → `CameraPreviewPage`

다음 서비스 라우트는 만들지 않는다.

* `/auth`
* `/onboarding`
* `/onboarding/grade`
* `/solve/camera`
* `/camera/review`
* `/mypage/history`
* `/mypage/profile`

OAuth 라이브러리가 별도의 callback 경로를 반드시 요구하는 경우에는 임의로 추가하지 말고, 필요한 경로와 이유를 분석 단계에서 보고하여 승인받아라.

`/mypage`의 학습 기록과 프로필은 별도 라우트가 아니라 `MyPage` 내부 영역 또는 탭으로 구성할 예정이다. 이번 단계에서는 실제 탭 UI를 구현하지 않는다.

페이지 폴더는 다음 구조를 기준으로 한다.

```text
apps/web/src/pages/
├── login/
├── grade-setup/
├── solve/
├── mypage/
├── camera/
│   └── preview/
└── not-found/
```

카메라 기능 경로는 반드시 다음으로 통일한다.

```text
apps/web/src/features/camera
```

`features/photo-capture`는 사용하지 않는다.

이번 단계에서는 카메라 라우트와 페이지 진입점만 구성한다. 실제 카메라 접근, 촬영, 이미지 저장 및 이미지 분석 기능은 구현하지 않는다.

# 4. 추가 결정사항 확정

## 4.1 pnpm

Corepack 방식을 승인한다.

실행 전에 다음을 확인해라.

* Node.js 버전
* Corepack 설치 여부와 버전
* pnpm 11.17.0 호환 여부

Node.js 22 이상을 기준으로 하며 권장 순서는 다음과 같다.

```bash
node --version
corepack --version
corepack enable pnpm
corepack use pnpm@11.17.0
pnpm --version
```

루트 `package.json`에는 다음을 명시한다.

```json
{
  "packageManager": "pnpm@11.17.0",
  "engines": {
    "node": ">=22"
  }
}
```

Corepack이 없거나 정상 작동하지 않을 때만 추가 설치 필요성을 보고하고 승인받아라.

## 4.2 iPad 최소 지원 너비

iPad 가로 전체 화면의 최소 지원 너비를 `1024 CSS px`로 확정한다.

* `window.innerWidth < 1024`이면 최소 너비 미달로 판단한다.
* `screen.width`는 사용하지 않는다.
* 세로모드는 너비와 별도로 orientation으로 판단한다.
* 세로모드에서는 “기기를 가로로 돌려주세요”를 표시한다.
* 가로모드이지만 1024px 미만이면 “전체 화면에서 이용해 주세요”를 표시한다.
* 1024px 이상이면 정상 화면을 표시한다.
* 안내 화면이 표시되어도 URL을 변경하지 않는다.
* Figma 기준 1194×834에서 가장 정확하게 구현한다.
* 1024~1193px에서도 화면이 잘리거나 깨지지 않도록 유동적으로 대응한다.

`ViewportGuard`는 인증 가드나 React Router의 라우팅 책임과 분리한다.

다음 후보를 현재 구조에 맞게 비교한 후 가장 역할이 명확한 위치를 제안해라.

* `apps/web/src/app/App.tsx`
* `apps/web/src/app/providers.tsx`
* `apps/web/src/shared/ui/viewport-guard/ViewportGuard.tsx`

`ViewportGuard`는 화면 환경만 검사하고, 로그인 여부를 검사하거나 URL을 변경하면 안 된다.

## 4.3 `/` 진입 정책

`/`는 인증 상태에 따라 분기한다.

* 세션 확인 중: 최소 로딩 화면
* 비로그인 사용자: `/login`으로 replace 이동
* 로그인 사용자: `/solve`로 replace 이동

인증 상태와 관계없이 `/solve`로 보내는 임시 정책은 사용하지 않는다.

## 4.4 NotFoundPage

`*` 와일드카드 라우트와 최소 `NotFoundPage`를 포함한다.

이는 Figma의 공식 서비스 화면이 아니라 잘못된 URL을 처리하기 위한 기술적 예외 페이지다.

이번 단계에서는 다음만 제공한다.

* 페이지를 찾을 수 없다는 안내
* `/solve`로 이동하는 텍스트 링크

최종 UI 디자인은 구현하지 않는다.

## 4.5 TypeScript

다음 split 구조를 사용한다.

```text
apps/web/
├── tsconfig.json
├── tsconfig.app.json
└── tsconfig.node.json
```

* `tsconfig.json`: project references
* `tsconfig.app.json`: React 브라우저 코드
* `tsconfig.node.json`: Vite 및 Vitest 설정 파일

루트 `tsconfig.base.json`과 중복되거나 충돌하는 옵션이 없도록 구성한다.

## 4.6 Vitest

`vitest.config.ts` 분리를 승인한다.

`vitest.config.ts`가 `vite.config.ts`를 자동 상속한다고 가정하지 마라.

* 공유 설정이 없으면 독립된 최소 설정을 사용한다.
* alias 등 공유가 필요하면 `mergeConfig` 등을 이용해 명시적으로 병합한다.
* Tailwind와 PWA 플러그인을 테스트 환경에 불필요하게 로드하지 않는다.

## 4.7 PWA 이름

다음 값으로 확정한다.

```text
name: 왜수학
short_name: 왜수학
display: standalone
orientation: landscape
start_url: /
```

확정되지 않은 부제나 영문 브랜드명을 임의로 추가하지 않는다.

기존 앱 아이콘이 없으면 임의 아이콘을 만들지 말고 필요한 파일만 보고한다.

PWA의 `orientation: landscape`가 일반 브라우저의 화면 회전을 완전히 강제한다고 설명하지 마라.

단, 정확한 설치 버전은 현재 Node.js, Vite, React, Vitest 버전과 호환되는지 확인하여 신규 직접 의존성 표에 기재한다.

# 5. AUTH 요구사항

`docs/PRD_WHYMATH.md`의 다음 요구사항을 기준으로 구현한다.

```md
| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| AUTH-1 | 소셜 로그인: Google, Apple, 카카오 중 최소 2개 제공. 버튼 1회 탭으로 가입과 로그인이 동시에 처리된다. | P0 | 첫 탭 → 로그인 완료까지 5초 이내 |
| AUTH-2 | 이메일 가입: 이메일 + 비밀번호만 입력. 이메일 인증은 가입 차단 없이 사후 처리. | P0 | 입력 필드 2개 초과 금지 |
| AUTH-3 | 세션 유지: 재방문 시 자동 로그인. | P0 | 30일 세션 유지 |
| AUTH-4 | 미성년자 대상 서비스로서 수집 정보 최소화(이메일, 닉네임, 학년만 수집). | P0 | 개인정보 항목 3개 이하 |
```

AUTH 표에 다음 요구사항을 추가한다.

```md
| AUTH-5 | 로그인 성공 후 이동: 이메일 또는 소셜 로그인이 완료되면 `/solve` 화면으로 이동한다. | P0 | 모든 로그인 방식에서 인증 성공 후 `/solve` 진입 |
| AUTH-6 | 인증 라우트 보호: 비로그인 사용자가 `/grade-setup`, `/solve`, `/mypage`, `/camera`, `/camera/preview`에 접근하면 `/login`으로 이동한다. | P0 | 보호 화면 직접 접근 시 `/login`으로 이동 |
| AUTH-7 | 로그인 화면 중복 접근 방지: 로그인한 사용자가 `/login`에 접근하면 `/solve`로 이동한다. | P1 | 인증 세션 확인 후 `/solve`로 replace 이동 |
```

# 6. 인증 Provider 확인 원칙

현재 저장소와 PRD에서 인증 Provider가 확정되어 있는지 먼저 확인한다.

* 기존 인증 Provider와 SDK가 있으면 이를 우선 사용한다.
* 인증 Provider가 문서와 코드 어디에도 확정되어 있지 않다면 Supabase, Firebase, Auth0 등을 임의로 선택하지 않는다.
* Provider가 미확정이면 선택 가능한 방식, 필요한 직접 의존성, 환경변수, 외부 콘솔 설정과 장단점을 보고하고 결정을 기다린다.
* 기존 Supabase 설정이 확인되는 경우에만 현재 Supabase 구조를 유지해 확장한다.
* OAuth Provider는 Figma, PRD 또는 기존 설정에서 확인된 것을 우선한다.
* Google, Apple, 카카오 중 어떤 2개를 구현할지 근거가 없으면 임의 선택하지 말고 결정사항으로 보고한다.

OAuth 키, secret 또는 실제 인증정보를 코드에 하드코딩하지 않는다.

`.env.example`에는 변수명과 설명만 추가하고 실제 값은 넣지 않는다.

# 7. 인증 상태와 라우팅

인증 상태를 최소한 다음 세 가지로 구분한다.

```text
loading
authenticated
unauthenticated
```

앱 최초 진입 시 세션 복원이 끝나기 전에 `/login`으로 이동시키지 마라.

`loading` 상태에서는 기존 Figma UI를 추측하지 않은 최소 로딩 화면을 표시한다.

## 로그인 성공

이메일 로그인과 모든 소셜 로그인에서 인증 성공 후 반드시 다음 방식으로 이동한다.

```ts
navigate('/solve', { replace: true })
```

요구사항:

* 로그인 성공 후 뒤로가기로 로그인 화면에 돌아가지 않게 처리
* 로그인 실패 시 `/login` 유지
* 실패 원인을 이해할 수 있는 오류 메시지 표시
* OAuth callback 완료 후에도 최종 목적지는 `/solve`
* 기존 접근 경로를 저장하거나 `returnTo`로 복귀시키지 않음

## 루트 진입

* 비로그인 상태로 `/` 접속 → `/login`
* 로그인 상태로 `/` 접속 → `/solve`

## 보호 라우트

다음 라우트는 로그인한 사용자만 접근할 수 있다.

* `/grade-setup`
* `/solve`
* `/mypage`
* `/camera`
* `/camera/preview`

각 페이지에서 인증 여부를 중복 검사하지 말고 공통 `ProtectedRoute` 또는 역할이 동일한 단일 인증 가드에서 처리한다.

비로그인 사용자가 보호 라우트에 접근하면 `/login`으로 replace 이동한다.

## 로그인 화면

로그인 사용자가 `/login`에 접근하면 `/solve`로 replace 이동한다.

`PublicOnlyRoute` 또는 역할이 명확한 동일 구조를 사용한다.

## 학년 설정

로그인 성공 직후에는 학년 설정 여부와 관계없이 `/solve`로 이동한다.

`/grade-setup`을 로그인 성공 직후의 필수 온보딩으로 사용하지 않는다.

실제 문제 풀이 과정에서 학년 정보가 필요할 때만 학년 설정을 안내하거나 `/grade-setup`으로 이동할 수 있도록 인증 흐름과 분리한다.

## 로그아웃

로그아웃 성공 시 인증 세션과 앱 내부 사용자 상태를 정리하고 `/login`으로 replace 이동한다.

# 8. AUTH 수용 기준 구현 시 주의사항

다음 사항은 프런트엔드 코드만으로 달성했다고 주장하지 마라.

## 이메일 인증 사후 처리

이메일 인증 때문에 가입 또는 최초 로그인이 차단되지 않도록 하는 설정은 인증 Provider의 콘솔 또는 서버 정책이 필요할 수 있다.

현재 Provider에서 가능한 방식과 필요한 외부 설정을 보고한다. 설정을 확인하지 않은 상태에서 AUTH-2가 완료됐다고 표시하지 않는다.

## 30일 세션 유지

30일 세션은 단순히 토큰을 직접 `localStorage`에 저장해 구현하지 않는다.

인증 Provider의 refresh token, 세션 만료 정책 및 보안 설정을 사용한다. Provider 측 설정 확인이 필요하면 정확히 보고한다.

## 개인정보 최소 수집

수집 가능한 사용자 정보는 다음으로 제한한다.

* 이메일
* 닉네임
* 학년

비밀번호는 인증용 보안정보로 취급하고 로그, 분석 이벤트 또는 프로필 데이터에 저장하지 않는다.

전화번호, 생년월일, 성별, 실명, 주소 등의 정보를 임의로 추가하지 않는다.

# 9. Tailwind CSS 4와 스타일

Tailwind CSS 4는 다음 방식으로 구성한다.

* Vite 연결: `@tailwindcss/vite`
* 디자인 토큰 연결: CSS-first `@theme`
* 기존 설정이 있으면 먼저 분석하고 불필요하게 교체하지 않는다.

권장 스타일 구조:

```text
apps/web/src/shared/styles/
├── tokens.css
├── theme.css
├── global.css
└── safe-area.css
```

역할:

* `tokens.css`: Figma에서 확인된 CSS Variables
* `theme.css`: Tailwind `@theme` 매핑
* `global.css`: reset, body, 기본 배경과 글자색
* `safe-area.css`: iPad safe area 처리

이번 단계에서는 Figma에서 확정된 색상만 이식한다.

Radius와 Spacing은 다음 절차를 거치기 전까지 임의로 만들지 않는다.

1. Figma raw 값 실측
2. 반복값 식별
3. 토큰 후보표 작성
4. 사용자 승인
5. 승인된 값만 코드 반영

# 10. 라이트 모드

v1에서는 다크모드를 지원하지 않는다.

* `dark:` 클래스를 사용하지 않는다.
* 다크모드 토큰을 만들지 않는다.
* 시스템 다크모드를 자동 적용하지 않는다.
* 전역 스타일에 `color-scheme: light`를 적용한다.
* 테마 전환 기능을 만들지 않는다.

# 11. 이번 단계에서 구현하지 않을 항목

다음은 구현하지 않는다.

* 실제 Figma 화면의 최종 UI
* Button, Card, Input 등 공통 UI의 최종 디자인
* 카메라 촬영 API
* 촬영 이미지 저장 및 분석
* 마이페이지 실제 데이터
* `ChatBubble`
* `MathActivityCard`
* `HistoryRow`
* 임의의 Radius 또는 Spacing 토큰
* 다크모드
* Figma에 없는 화면이나 상태
* 임의의 앱 아이콘
* Git commit

단, 인증 동작 검증에 반드시 필요한 최소 로그인 UI가 현재 저장소에 없다면 필요한 범위와 파일을 먼저 분석 결과에 포함한다.

# 12. 신규 직접 의존성 승인

패키지를 설치하기 전에 모든 신규 직접 의존성을 하나의 표로 보고한다.

표에는 다음 항목을 포함한다.

* 패키지명
* 정확한 버전
* `dependencies` 또는 `devDependencies`
* 사용 목적
* 현재 저장소에 이미 존재하는지
* 기존 구성으로 대체 가능한지
* 필수 또는 선택
* 선택한 버전의 근거

인증 SDK와 OAuth 관련 패키지도 반드시 이 표에 포함한다.

하위 의존성은 개별 승인 대상으로 나열하지 않는다.

내가 직접 의존성 목록을 일괄 승인한 뒤에만 설치한다. 승인 후 새로운 직접 의존성이 필요하면 다시 승인을 요청한다.

# 13. 작업 절차

이번 요청은 두 단계로 진행한다.

## 1단계: 읽기 전용 분석

아직 파일을 생성하거나 수정하지 말고 다음 순서로 보고한다.

1. 확인한 문서와 문서 간 충돌 여부
2. 현재 저장소 구조와 기존 설정
3. 기존 Node.js, Corepack, pnpm 상태
4. 이미 설치된 직접 의존성
5. 현재 인증 Provider와 SDK
6. 현재 인증 상태 관리 및 세션 복원 방식
7. 로그인 성공 처리 위치
8. OAuth callback 처리 방식
9. 현재 라우터와 가드 구조
10. 신규 직접 의존성 승인 표
11. 생성할 파일
12. 수정할 파일
13. 각 파일의 변경 목적
14. 최종 라우트 트리
15. 페이지 폴더 구조
16. `ViewportGuard` 위치와 책임
17. 인증 Provider 및 Auth 가드 설계
18. Tailwind CSS 4 연결 방식
19. PWA 설정 방식
20. 색상 토큰 이식 대상과 Figma 근거
21. typecheck, lint, test, build 검증 방법
22. 외부 인증 콘솔에서 별도로 설정해야 하는 항목
23. 이번 단계에서 구현하지 않을 항목
24. 추가로 결정이 필요한 사항

분석 결과만 보여주고 내 승인을 기다려라.

승인 전에는 다음 행동을 하지 마라.

* 파일 생성 또는 수정
* 패키지 설치
* 자동 포맷팅
* 라우트 구현
* 인증 구현
* 임시 페이지 구현
* PWA 설정 변경
* Git commit

## 2단계: 승인 후 구현

내가 분석 결과와 신규 직접 의존성을 승인하면 승인된 범위만 구현한다.

구현 원칙:

* 기존 동작과 구조를 최대한 보존
* 중복 파일 생성 금지
* 페이지별 인증 검사 금지
* `ViewportGuard`와 Auth 가드 책임 분리
* 인증정보 하드코딩 금지
* `any`로 타입 오류 회피 금지
* 승인받지 않은 패키지 설치 금지
* Figma 디자인 추측 금지
* Git commit 금지

# 14. 필수 테스트

최소한 다음 동작을 테스트한다.

## 라우팅

1. 세션 확인 중에는 잘못된 리다이렉트가 발생하지 않음
2. 비로그인 사용자의 `/` 접속 → `/login`
3. 로그인 사용자의 `/` 접속 → `/solve`
4. 로그인 성공 → `/solve`
5. 로그인 사용자의 `/login` 접근 → `/solve`
6. 비로그인 사용자의 보호 라우트 접근 → `/login`
7. 로그아웃 성공 → `/login`
8. 잘못된 URL → `NotFoundPage`

## ViewportGuard

1. 세로모드 → “기기를 가로로 돌려주세요”
2. 가로모드 1024px 미만 → “전체 화면에서 이용해 주세요”
3. 가로모드 1024px 이상 → 정상 앱 표시
4. 가드 표시 전후 URL이 변경되지 않음

## 인증

1. 세션 복원 성공
2. 세션 복원 실패
3. 이메일 로그인 성공과 실패
4. 소셜 로그인 성공과 실패
5. OAuth callback 후 `/solve` 이동
6. 로그인 상태에서 페이지 새로고침 시 세션 유지
7. 인증 오류 메시지 노출
8. 프로필 또는 로그에 불필요한 개인정보가 저장되지 않음

외부 OAuth 계정이나 Provider 콘솔 설정 때문에 자동 테스트할 수 없는 항목은 테스트 완료로 표시하지 말고 수동 검증 항목으로 분리한다.
