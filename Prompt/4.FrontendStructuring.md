WhyMath 문서의 화면명과 라우트 네이밍 정리가 완료되었다.

이제 다음 단계로 프론트엔드 기반 구조를 구현하려고 한다.

가장 먼저 다음 문서를 읽고 현재 저장소 상태와 비교해라.

- docs/FIGMA_SCREEN_MAP.md
- docs/PRD_WHYMATH.md
- docs/PROJECT_STRUCTURE.md
- docs/FRONTEND_IMPLEMENTATION_PLAN.md
- docs/COMPONENT_MAP.md
- docs/DESIGN_SYSTEM.md
- docs/DESIGN_TOKEN_MAP.md
- CLAUDE.md
- .claude/rules/frontend.md

화면명과 라우트의 단일 기준은
`docs/FIGMA_SCREEN_MAP.md`로 한다.

이번 단계는 “화면 디자인 구현”이 아니라
“프론트엔드 기반 구조 및 라우팅 뼈대 구축” 단계다.

아직 코드를 수정하거나 패키지를 설치하지 말고,
먼저 현재 상태 분석과 구현 계획만 보고한 뒤 내 승인을 기다려라.

[1. 이번 단계의 구현 목표]

다음 범위만 구현 대상으로 한다.

1. pnpm workspace 기반 루트 설정
2. `apps/web` React + TypeScript + Vite 애플리케이션 초기화
3. Tailwind CSS 4 연결
4. 앱 진입점과 Provider 구조 구성
5. 확정된 6개 화면의 라우팅 뼈대 구성
6. iPad 가로 전체 화면 지원을 위한 전역 환경 가드 구성
7. PWA 기본 설정과 landscape orientation 보조 설정
8. 라이트 모드 고정
9. 확정된 Figma 색상 토큰만 CSS Variables로 이식
10. typecheck, lint, test, build 검증 명령 구성

이번 단계에서는 다음을 구현하지 않는다.

- 실제 Figma 화면 UI
- Button, Card 등 공통 UI의 최종 디자인
- 로그인 인증 로직
- 카메라 촬영 API
- 촬영 이미지 분석 로직
- 마이페이지의 실제 데이터
- ChatBubble
- MathActivityCard
- HistoryRow
- 임의의 Radius 또는 Spacing 토큰
- 다크모드
- Figma에 없는 화면이나 상태

[2. 프로젝트 구조 기준]

v1은 `apps/web` 단일 앱 중심으로 구현한다.

- Turborepo와 Nx는 도입하지 않는다.
- pnpm workspace만 사용한다.
- `packages/ui`
- `packages/shared-types`
- `packages/validation`

위 패키지는 현재 생성하지 않는다.

둘 이상의 앱이나 백엔드에서 타입을 실제로 공유하게 될 때만
`packages/contracts` 도입을 검토한다.

공통 코드의 위치는 다음 기준을 사용한다.

- 앱 설정 및 라우팅: `apps/web/src/app`
- 페이지 조립: `apps/web/src/pages`
- 기능 코드: `apps/web/src/features`
- 공통 UI: `apps/web/src/shared/ui`
- 디자인 토큰 및 전역 스타일: `apps/web/src/shared/styles`

[3. 확정 라우트]

`docs/FIGMA_SCREEN_MAP.md`를 기준으로
다음 라우트만 구성한다.

1. 로그인
   - Figma: `1. Login/Desktop`
   - Route: `/login`
   - Page: `LoginPage`

2. 학년 선택
   - Figma: `2. Grade Setup`
   - Route: `/grade-setup`
   - Page: `GradeSetupPage`

3. 문제 풀기
   - Figma: `3 · Solve/Landscape`
   - Route: `/solve`
   - Page: `SolvePage`

4. 마이페이지
   - Figma: `4 · MyPage`
   - Route: `/mypage`
   - Page: `MyPage`

5. 문제 촬영
   - Figma: `5 · Capture.Camera`
   - Route: `/camera`
   - Page: `CameraCapturePage`

6. 촬영 결과 미리보기
   - Figma: `6 · preview.Camera`
   - Route: `/camera/preview`
   - Page: `CameraPreviewPage`

다음 라우트는 생성하지 않는다.

- `/auth`
- `/onboarding`
- `/onboarding/grade`
- `/solve/camera`
- `/camera/review`
- `/mypage/history`
- `/mypage/profile`

`/mypage`의 학습 기록과 프로필은 별도 라우트가 아니라
`MyPage` 내부 영역 또는 탭으로 구성할 예정이다.

이번 단계에서는 실제 탭 UI를 구현하지 않는다.

[4. 페이지 폴더 구조]

카메라 페이지는 다음 중첩 폴더 구조를 사용한다.

apps/web/src/pages/
- login/
- grade-setup/
- solve/
- mypage/
- camera/
  - preview/

기능 경로는 반드시 다음으로 통일한다.

- `apps/web/src/features/camera`

`features/photo-capture`는 사용하지 않는다.

카메라 라우팅은 다음 구조로 설계한다.

- `/camera` → `CameraCapturePage`
- `/camera/preview` → `CameraPreviewPage`

이번 단계에서는 라우트와 페이지 진입점만 구성한다.
실제 카메라 접근, 촬영, 이미지 저장 기능은 구현하지 않는다.

미리보기 데이터 가드는 실제 카메라 상태 구현 단계에서 추가하되,
추후 `features/camera`의 촬영 데이터 존재 여부를 확인하여
데이터가 없으면 `/camera`로 이동시키는 구조가 가능하도록 설계한다.

임시 촬영 데이터는 URL 또는 공통 전역 Store에 저장하지 않는다.

[5. iPad 가로 환경 가드]

v1의 공식 지원 환경은 1194×834 기준
iPad 가로 전체 화면이다.

전역 환경 가드는 React Router의 별도 라우트가 아니라
앱 최상위 레이아웃에서 처리한다.

요구사항:

1. 세로 방향이면
   “기기를 가로로 돌려주세요” 안내 화면을 표시한다.

2. Split View 등으로 지원 최소 너비보다 작으면
   “전체 화면에서 이용해 주세요” 안내 화면을 표시한다.

3. 안내 화면이 표시되어도 현재 URL은 변경하지 않는다.

4. 일반 브라우저에서 화면 방향을 강제로 고정한다고 가정하지 않는다.

5. PWA로 설치된 환경에서는 가능한 경우에만
   landscape orientation을 보조 적용한다.

최소 지원 너비는 Figma 기준과 문서를 다시 확인한 뒤 보고해라.
근거 없이 임의 값을 적용하지 마라.

전역 환경 가드의 권장 위치를 다음 후보와 함께 비교해라.

- `apps/web/src/app/App.tsx`
- `apps/web/src/app/providers.tsx`
- 전용 `ViewportGuard` 컴포넌트

역할 분리가 명확한 구조를 제안하되,
승인 전에는 구현하지 마라.

[6. Tailwind CSS 4와 스타일]

Tailwind CSS 4는 다음 방식으로 구성한다.

- Vite 연결: `@tailwindcss/vite`
- 디자인 토큰 연결: CSS-first `@theme`
- 기존 설정이 있다면 먼저 분석하고 불필요하게 교체하지 않는다.

권장 스타일 구조:

apps/web/src/shared/styles/
- tokens.css
- theme.css
- global.css
- safe-area.css

역할:

- `tokens.css`: Figma에서 확인된 CSS Variables
- `theme.css`: Tailwind `@theme` 매핑
- `global.css`: reset, body, 기본 배경과 글자색
- `safe-area.css`: iPad safe area 처리

이번 단계에서는 Figma에서 확정된 색상만 이식한다.

Radius와 Spacing은 다음 작업에서 별도로 진행한다.

- Figma raw 값 실측
- 반복값 식별
- 토큰 후보표 작성
- 사용자 승인
- 승인된 값만 코드 반영

임의의 Radius 또는 Spacing 스케일을 만들지 마라.

[7. 다크모드]

v1에서는 다크모드를 지원하지 않는다.

- `dark:` 클래스를 사용하지 않는다.
- 다크모드 토큰을 만들지 않는다.
- 시스템 다크모드를 자동 적용하지 않는다.
- 전역 스타일에 `color-scheme: light`를 적용한다.
- 테마 전환 기능을 만들지 않는다.

[8. PWA 설정]

PRD에 확정된 `vite-plugin-pwa` 사용 여부와
현재 저장소 설정을 먼저 확인한다.

사용 시 기본 방향은 다음과 같다.

- `display: standalone`
- `orientation: landscape`
- 앱 이름과 short_name은 PRD 또는 기존 문서 값 사용
- 임의의 앱 아이콘을 생성하지 않음
- 기존 아이콘이 없으면 필요한 파일만 보고
- 오프라인 캐시 범위는 이번 단계에서 최소화

PWA 설정이 화면 강제 회전을 완전히 보장한다고 설명하지 마라.

[9. 신규 npm 의존성 승인]

패키지를 설치하기 전에 신규 직접 의존성을 표로 보고한다.

표에는 다음 항목을 포함한다.

- 패키지명
- 정확한 버전
- dependencies 또는 devDependencies
- 사용 목적
- 현재 저장소에 이미 존재하는지
- 기존 구성으로 대체 가능한지
- 필수 또는 선택
- 선택한 버전의 근거

하위 의존성은 개별 승인 대상으로 나열하지 않는다.

내가 직접 의존성 목록을 일괄 승인한 뒤에만 설치한다.
승인 후 새로운 직접 의존성이 필요하면 다시 승인을 요청한다.
