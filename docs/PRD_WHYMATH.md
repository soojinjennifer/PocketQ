# PRD — 수학 개념 튜터 "포켓큐" (PocketQ)

궁금증이 풀릴 때까지 답해주는 iPad 수학 학습 웹서비스

- 버전 1.1 | 2026-07-14 | 작성: soojin.jennifer
- 용도: AI 코딩 도구(Claude Code 등) 입력용 개발 명세
- v1.1 변경: AI 제공자를 Claude / OpenAI GPT 중 선택 가능하도록 수정

---

## 1. 개요

### 1.1 배경 및 문제 정의

중·고등학생이 혼자 수학 문제를 풀다 막혔을 때 도움을 받을 곳이 마땅치 않다. 학원에서는 문제 풀이 절차만 알려주고 개념 설명은 생략하는 경우가 많아, 학생은 "왜 이렇게 푸는지", "이 문제가 어떤 개념과 연결되는지"를 이해하지 못한 채 넘어간다. 개념은 결국 혼자 공부해야 하고, 궁금한 점을 물어볼 상대가 없어 학습이 단절된다.

본 서비스는 학생이 문제를 사진으로 찍거나 Apple Pencil로 직접 써서 입력하면, AI가 해당 문제와 관련된 개념 설명과 풀이 과정을 함께 제공하고, 궁금증이 완전히 풀릴 때까지 후속 질문에 답해주는 iPad 최적화 웹서비스이다.

### 1.2 제품 목표

- 풀이 절차 암기가 아닌 개념 이해 중심의 학습을 지원한다.
- 문제 입력부터 개념+풀이 확인까지 3번의 터치 이내로 도달하게 한다.
- 학생이 답을 본 후에도 "왜?"를 계속 물을 수 있는 대화형 학습 경험을 제공한다.
- 풀었던 문제를 개념별로 축적해 자신만의 개념 노트가 되게 한다.

### 1.3 대상 사용자

- 주 사용자: 중학교 1학년 ~ 고등학교 3학년 학생 (한국 수학 교육과정 기준)
- 주 사용 기기: iPad + Apple Pencil (Safari 브라우저 기반 웹 앱)

### 1.4 성공 지표 (MVP 기준)

| 지표 | 정의 | 목표 |
|---|---|---|
| 풀이 완료율 | 문제 입력 시작 → 결과 확인 완료 비율 | 80% 이상 |
| 후속 질문율 | 결과 확인 후 1회 이상 추가 질문한 세션 비율 | 40% 이상 |
| 주간 재방문율 | 가입 후 7일 내 재방문 비율 | 50% 이상 |
| 풀이 응답 시간 | 풀기 버튼 → 첫 응답 출력 시작 | 5초 이내 |

## 2. 사용자 페르소나 및 핵심 시나리오

### 2.1 페르소나

"지민" — 고등학교 1학년. 학원 숙제 중 이차함수 최댓값 문제에서 막혔다. 학원 선생님의 풀이는 봤지만 "왜 꼭짓점에서 최댓값이 되는지"가 이해되지 않는다. 밤 10시, 물어볼 사람이 없다.

### 2.2 핵심 시나리오 (Happy Path)

1. 지민이 iPad에서 서비스에 접속해 소셜 로그인(5초)으로 들어간다.
2. 첫 로그인 시 학년(고1)을 선택한다. 시스템은 고1 교육과정 문제은행/개념 체계를 컨텍스트로 준비한다.
3. "문제 풀기" 화면에서 "문제 사진찍기"를 선택해 문제집을 촬영한다.
4. "개념설명해주기"와 "풀이해주기"를 모두 체크하고 "풀기"를 누른다.
5. 하단에 관련 개념(이차함수의 표준형과 꼭짓점) 설명, 단계별 풀이, 최종 답이 표시된다.
6. 지민이 후속 질문 입력창에 "왜 꼭짓점에서 최댓값이 돼?"라고 묻고, AI가 그래프 개형과 함께 설명한다. 궁금증이 풀릴 때까지 반복한다.
7. 이 문제는 "이차함수 > 최대·최소" 개념으로 분류되어 마이페이지에 자동 저장된다.

## 3. 정보 구조 및 화면 구성

MVP는 3개 화면 + 온보딩으로 구성된다(문제 풀기 화면 내 카메라 촬영/미리보기 하위 플로우 포함, 개발 라우트 최종 기준은 `docs/FIGMA_SCREEN_MAP.md` 참고).

| 화면 | 핵심 역할 | 경로(개발 라우트) |
|---|---|---|
| 로그인 | 이메일·소셜 계정으로 5초 내 로그인 | /login |
| 회원가입 | 이메일·소셜 계정으로 5초 내 가입 | /register |
| 온보딩(학년 선택) | 학년 선택 → 교육과정 컨텍스트 설정 | /grade-setup |
| 문제 풀기 (메인) | 문제 입력(사진/필기) → 옵션 선택 → 결과 + 후속 질문 | /solve |
| 문제 촬영 | 문제 풀기 내 사진 입력 하위 플로우 — 카메라 촬영 | /camera |
| 촬영 결과 미리보기 | 문제 풀기 내 사진 입력 하위 플로우 — 촬영 확인/재촬영 | /camera/preview |
| 마이페이지 | 풀이 이력 리스트(개념 분류) 및 다시 보기 | /mypage |

하단 탭 내비게이션: [문제 풀기] [마이페이지] 2개 탭. 문제 풀기가 기본(홈) 화면.

## 4. 기능 요구사항 (Functional Requirements)

우선순위: P0 = MVP 필수, P1 = MVP 포함 권장, P2 = 로드맵.

### 4.1 회원가입 및 로그인 (AUTH)

| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| AUTH-1 | 소셜 로그인: Google, Apple, 카카오 중 최소 2개 제공. 버튼 1회 탭으로 가입과 로그인이 동시에 처리된다. | P0 | 첫 탭 → 로그인 완료까지 5초 이내 |
| AUTH-2 | 이메일 가입: 닉네임(또는 이름) + 이메일 + 비밀번호 입력. 이메일 인증은 가입 차단 없이 사후 처리. | P0 | 입력 필드 3개 초과 금지 |
| AUTH-3 | 세션 유지: 재방문 시 자동 로그인. | P0 | 30일 세션 유지 |
| AUTH-4 | 미성년자 대상 서비스로서 수집 정보 최소화(이메일, 닉네임, 학년만 수집). | P0 | 개인정보 항목 3개 이하 |
| AUTH-5 | 로그인 성공 후 이동: 이메일 또는 소셜 로그인이 완료되면, 학년이 아직 설정되지 않은 사용자는 `/grade-setup`으로, 학년이 설정된 사용자는 `/solve`로 이동한다. 회원가입 완료 직후에는 자동 로그인 상태로 두지 않고 `/login`으로 이동시켜 별도로 로그인하게 한다. | P0 | 최초 로그인(학년 미설정) 시 `/grade-setup` 진입, 이후 로그인은 `/solve` 진입, 회원가입 직후에는 `/login`으로 이동 |
| AUTH-6 | 인증 라우트 보호: 비로그인 사용자가 `/grade-setup`, `/solve`, `/mypage`, `/camera`, `/camera/preview`에 접근하면 `/login`으로 이동한다. | P0 | 보호 화면 직접 접근 시 `/login`으로 이동 |
| AUTH-7 | 공개 인증 화면 접근 제한: 로그인한 사용자가 `/login` 또는 `/register`에 접근하면 `/solve`로 이동한다. | P1 | 세션 확인 후 `/solve`로 replace 이동 |
| AUTH-8 | 이메일 회원가입 화면 분리: 이메일 회원가입은 독립된 `/register` 화면에서 처리하고 로그인 화면은 로그인만 담당한다. | P0 | 로그인과 회원가입 기능 및 라우트가 분리되어 동작 |
| AUTH-9 | 이메일 찾기: 로그인 화면에서 "이메일을 잊었어요!" 선택 시, **이 기기에 남아있는 로그인 세션 정보**로 회원가입 시 사용한 닉네임과 이메일을 "{닉네임}님, 가입하신 이메일은 {이메일}입니다" 팝업으로 보여주고 확인을 받은 뒤 로그인 이메일 입력란에 자동으로 채워준다. 이메일은 마스킹 없이 전체로 표시한다. 이 기기에 로그인 이력이 없으면 "이 기기에서 로그인한 기록이 없어요. 회원가입을 진행하시겠어요?" 팝업을 확인/취소 버튼과 함께 띄운다. 확인 시 `/register`로 이동하고, 취소 시 팝업만 닫고 로그인 화면에 머무른다. 별도 라우트 없이 로그인 화면 위 팝업으로만 처리한다. | P1 | 이 기기에서 로그인한 적이 있으면 "{닉네임}님, 가입하신 이메일은 {이메일}입니다" 팝업 표시 → 확인 시 이메일 입력란 자동 채움. 로그인 이력이 없으면 "이 기기에서 로그인한 기록이 없어요. 회원가입을 진행하시겠어요?" 팝업이 확인/취소 버튼과 함께 표시 → 확인 시 `/register`로 이동, 취소 시 팝업이 닫히고 로그인 화면 유지 |

| AUTH-10 | 비밀번호 찾기/재설정: 로그인 화면 이메일 입력란에 이메일을 입력한 뒤 "비밀번호를 잊었어요!" 선택 시, Supabase가 해당 이메일로 8자리 인증 코드를 발송하고, "인증 코드 입력" 팝업에 발송 대상 이메일과 코드 입력란을 보여준다. 코드를 확인하면 같은 팝업이 이메일 표시 + 새 비밀번호·비밀번호 확인 입력 단계로 전환된다. 두 입력값이 일치하면 Supabase의 비밀번호가 갱신되고 "비밀번호가 변경되었습니다. 다시 로그인해주세요" 팝업이 표시된다. 확인하면 팝업이 닫히고 로그인 화면 이메일 입력란에 해당 이메일이 채워진 채로 비밀번호 입력을 기다린다. 코드가 틀리거나 만료된 경우 이메일 존재 여부를 노출하지 않는 일반적인 오류 메시지("인증 코드가 올바르지 않거나 만료됐어요")를 표시하고 재입력·재전송할 수 있다. 별도 라우트 없이 로그인 화면 위 팝업으로만 처리한다. | P1 | "비밀번호를 잊었어요!" 선택 시 인증 코드 발송 및 코드 입력 팝업 표시. 올바른 코드 입력 시 이메일 표시 + 새 비밀번호/확인 입력 단계로 전환. 두 입력값 불일치 시 제출 차단. 성공 시 "다시 로그인해주세요" 안내 후 로그인 화면으로 복귀하며 이메일 입력란 자동 채움. 코드 오류/만료 시 이메일 존재 여부를 드러내지 않는 재시도 가능한 오류 메시지 표시 |

### 4.2 학년 설정 및 교육과정 컨텍스트 (GRADE)

| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| GRADE-1 | 첫 로그인 시 학년 선택 화면 표시: 중1~중3, 고1~고3 (6개 선택지). | P0 | 1탭으로 선택 완료 |
| GRADE-2 | 선택된 학년에 해당하는 한국 수학 교육과정 개념 체계와 문제은행 메타데이터를 AI 컨텍스트로 로드하여 "준비 상태"로 대기한다. 이후 풀이 요청 시 이 컨텍스트가 시스템 프롬프트에 포함된다. | P0 | 풀이 결과가 해당 학년 교육과정 용어·범위로 설명됨 |
| GRADE-3 | 학년은 마이페이지에서 언제든 변경 가능. | P1 | 변경 즉시 컨텍스트 반영 |

### 4.3 문제 풀기 화면 — 문제 입력 (INPUT)

화면 상단 영역에 입력 방식 선택 세그먼트 컨트롤: [문제 사진찍기] | [직접 쓰기].

| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| INPUT-1 | "직접 쓰기" 선택 시: Apple Pencil로 필기할 수 있는 캔버스 영역이 상단에 표시된다. 팜 리젝션(손바닥 무시), 지우개, 전체 지우기, 실행 취소를 지원한다. | P0 | Pencil 필기 지연 50ms 이하 체감, 손바닥 오입력 없음 |
| INPUT-2 | "문제 사진찍기" 선택 시: 사진찍기 버튼이 활성화되고, 탭하면 카메라가 열린다(getUserMedia 또는 input capture). 촬영 후 미리보기와 재촬영 버튼을 제공한다. | P0 | 촬영 → 미리보기 표시 2초 이내 |
| INPUT-3 | 필기/사진 입력물은 Vision 모델(OCR + 수식 인식)로 문제 텍스트·수식(LaTeX)으로 변환된다. 변환 결과를 학생에게 보여주고 수정 기회를 제공한다. | P0 | 인식 결과 확인 UI 존재, 오인식 시 수정 가능 |
| INPUT-4 | 사진 앨범에서 기존 이미지 선택도 허용. | P1 | 카메라와 동일 플로우 |

### 4.4 문제 풀기 화면 — 풀이 옵션 및 실행 (SOLVE)

| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| SOLVE-1 | 입력 영역 아래에 멀티 체크박스 2개 제공: [개념설명해주기] [풀이해주기]. 둘 다 선택 가능, 최소 1개 선택 필수. | P0 | 0개 선택 시 풀기 버튼 비활성화 |
| SOLVE-2 | "풀기" 버튼 탭 시 선택된 옵션에 따라 AI가 응답을 생성하여 화면 하단 결과 영역에 스트리밍으로 표시한다. | P0 | 첫 토큰 5초 이내, 스트리밍 렌더링 |
| SOLVE-3 | 결과 구성: (a) 관련 개념 — 이 문제에 필요한 개념 이름, 정의, 핵심 원리, 왜 이 개념이 쓰이는지. (b) 단계별 풀이 — 각 단계에 "무엇을 하는지"와 "왜 하는지"를 함께 서술. (c) 최종 답 — 명확히 구분된 답 박스. | P0 | 개념/풀이/답 3개 섹션이 시각적으로 구분됨 |
| SOLVE-4 | 수식은 LaTeX 기반으로 렌더링한다(KaTeX 권장). | P0 | 분수·지수·근호 등 정상 표시 |
| SOLVE-5 | 풀이 결과는 학생의 학년 교육과정 범위 내 용어와 방법으로 설명한다. 상위 학년 개념이 필요한 경우 그 사실을 명시한다. | P0 | 학년 외 개념 사용 시 안내 문구 표시 |

### 4.5 후속 질문 대화 (CHAT)

#### 후속 질문 MVP 범위

후속 질문 P0 범위는 다음과 같다.

1. 동일 문제의 인식 결과와 최초 풀이 맥락 유지
2. 키보드 텍스트 질문 입력
3. 추천 질문 pill 선택
4. 빈 질문 및 중복 제출 방지
5. 질문 요청·성공·오류·재시도 처리
6. AI의 직접적인 답변과 개념·이유 설명
7. 새 문제 시작 시 현재 대화 초기화
8. ResultPanel Footer 도킹 및 대화 영역 스크롤
9. 사진 입력과 직접쓰기 입력에서 동일한 후속 질문 컴포넌트 사용

다음 항목은 현재 P0 범위에서 제외한다.

* Apple Pencil 필기 질문 입력
* 답변 생성 과정의 실시간 스트리밍 표시
* 음성 질문 입력

후속 대화의 Supabase 영구 저장과 마이페이지 재열람은 CHAT-4의 P1 범위에서 구현한다.

### 6.2 스타일링 원칙

1. 일반 레이아웃, 여백, 색상, 반응형 처리는 Tailwind CSS를 사용한다.
2. 색상, 글꼴, 간격, 모서리, 그림자는 CSS Variables 기반의 디자인 토큰으로 정의한다.
3. 임의 색상과 임의 픽셀값의 반복 사용을 금지한다.
4. 공통 UI는 Button, Card, Modal, Input, IconButton 등의 컴포넌트로 재사용한다.
5. 같은 Tailwind 클래스 조합이 3회 이상 반복되면 공통 컴포넌트 또는 Variant로 분리한다.

7. 컴포넌트 재사용은 Tailwind 클래스 복사가 아니라 공통 UI 컴포넌트와 props를 통해 구현한다.
8. Claude Design의 고정 좌표를 그대로 복사하지 않고 iPad 가로·세로 모드와 Split View에 대응하는 반응형 레이아웃으로 변환한다.

## 8. AI 동작 명세

### 8.1 시스템 프롬프트 핵심 지침 (제공자 공통)

- 너는 한국 중·고등학생을 위한 수학 개념 튜터다. 학생의 학년은 {grade}이며, 해당 교육과정 범위의 용어와 방법으로 설명한다.
- "개념설명해주기" 선택 시: 문제에 필요한 개념의 정의, 핵심 원리, 이 문제에서 왜 쓰이는지를 설명한다. 공식은 유도 배경과 함께 제시한다.
- "풀이해주기" 선택 시: 단계별 풀이를 제공하되, 각 단계마다 "무엇을" 하는지와 "왜" 하는지를 함께 쓴다. 마지막에 최종 답을 명확히 표기한다.
- 후속 질문에는 문제와 이전 대화 맥락을 유지하며, 학생의 궁금증이 풀릴 때까지 답한다. 이해를 확인하는 짧은 되물음은 허용하되 답변 회피는 금지.
- 응답 마지막에 이 문제의 개념 분류를 JSON으로 출력한다: `{"concept_tags": ["이차함수 > 최대·최소"]}` (파싱 후 저장, 화면에는 미표시).

시스템 프롬프트는 제공자와 무관하게 단일 소스로 관리하며, 어댑터가 각 제공자의 API 형식(system 파라미터 vs system 메시지)에 맞게 변환한다.

### 8.2 처리 파이프라인

1. 이미지(사진 또는 캔버스 PNG) 업로드 → Storage 저장.
2. Vision 모델로 문제 인식 → 텍스트/LaTeX 추출 → 학생 확인·수정. (선택된 AI 제공자의 vision 기능 사용)
3. 시스템 프롬프트(학년 컨텍스트 + 교육과정 단원 목록) + 문제 + 선택 옵션으로 풀이 생성(스트리밍).
4. 응답에서 concept_tags 파싱 → solutions 저장(ai_provider, ai_model 함께 기록) → 마이페이지 반영.

### 8.3 LLM Adapter 인터페이스 (구현 규약)

```typescript
interface LLMAdapter {
  /** 이미지에서 문제 텍스트/LaTeX 추출 */
  recognizeProblem(image: Buffer, grade: Grade): Promise<RecognizedProblem>;
  /** 개념/풀이 생성 — 스트리밍 */
  solve(req: SolveRequest): AsyncIterable<string>;
  /** 후속 질문 — 멀티턴, 스트리밍 */
  chat(req: ChatRequest): AsyncIterable<string>;
}

// 구현체 2개: ClaudeAdapter, OpenAIAdapter
// 팩토리: createAdapter(process.env.AI_PROVIDER, process.env.AI_MODEL)
```

- 환경변수: `AI_PROVIDER` (claude | openai), `AI_MODEL` (예: claude-sonnet-5, gpt-4o 등 vision+스트리밍 지원 모델), `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`.
- 두 어댑터는 동일한 시스템 프롬프트 소스를 사용하고, 동일한 출력 규약(마크다운 + 말미 concept_tags JSON)을 따른다.
- 스트리밍은 서버에서 SSE로 통일하여 클라이언트는 제공자를 인지하지 못한다.
